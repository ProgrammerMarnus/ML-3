[C-1] Alert factory rules crash on construction
File: monitoring/alerting.py
Funcs: create_sharpe_ratio_alert, create_drawdown_alert,
       create_prediction_error_alert, create_volume_spike_alert,
       AlertManager.threshold_condition
---------------------------------------------------------------------
PROBLEM
  The factories pass operators WITH spaces:
      condition=AlertManager.threshold_condition(min_sharpe, " < ")
  but threshold_condition looks them up in a dict keyed WITHOUT spaces:
      operators = {">": ..., "<": ..., ...}
      if operator not in operators: raise ValueError(...)
  So every pre-built alert raises ValueError the instant it is created.
  Second bug: AlertRule.check_and_trigger formats the message with
      threshold=getattr(self, 'threshold', None)
  but AlertRule has no threshold attribute, so messages print "None".

WHY IT MATTERS
  The whole alerting subsystem is unusable; drawdown/Sharpe alerts never work.

FIX
  1) Normalize the operator.
  2) Give AlertRule a threshold field so the template renders correctly.

  @dataclass
  class AlertRule:
      name: str
      metric_name: str
      condition: Callable[[float], bool]
      severity: AlertSeverity = AlertSeverity.WARNING
      cooldown_minutes: int = 60
      message_template: str = "{metric_name} triggered alert: {value}"
      enabled: bool = True
      last_triggered: Optional[datetime] = None
      threshold: Optional[float] = None          # <-- ADD THIS

      def check_and_trigger(self, value, context=None):
          if not self.enabled:
              return None
          if self.last_triggered:
              cooldown_end = self.last_triggered + timedelta(minutes=self.cooldown_minutes)
              if datetime.now() < cooldown_end:
                  return None
          if self.condition(value):
              self.last_triggered = datetime.now()
              message = self.message_template.format(
                  metric_name=self.metric_name,
                  value=value,
                  threshold=self.threshold,        # <-- now real
              )
              return Alert(name=self.name, message=message,
                           severity=self.severity, context=context or {})
          return None

  @staticmethod
  def threshold_condition(threshold: float, operator: str = ">"):
      operator = operator.strip()                # <-- FIX: strip spaces
      operators = {
          ">":  lambda x: x > threshold,
          "<":  lambda x: x < threshold,
          ">=": lambda x: x >= threshold,
          "<=": lambda x: x <= threshold,
          "==": lambda x: x == threshold,
          "!=": lambda x: x != threshold,
      }
      if operator not in operators:
          raise ValueError(f"Invalid operator: {operator!r}")
      return operators[operator]

  Then in each factory set threshold, e.g.:
      return AlertRule(
          name="low_sharpe_ratio",
          metric_name="sharpe_ratio",
          condition=AlertManager.threshold_condition(min_sharpe, "<"),  # no spaces
          severity=AlertSeverity.WARNING,
          message_template="Sharpe ratio dropped to {value} (below {threshold})",
          cooldown_minutes=1440,
          threshold=min_sharpe,                  # <-- ADD THIS
      )

File: run_paper_trader.py (root)
Func: PaperTradingSystem._load_previous_state
---------------------------------------------------------------------
PROBLEM
  It reads positions and logs "Loaded N previous positions" but never applies
  them to portfolio_manager/broker, and never restores cash/equity. On restart
  the whole persistence layer is defeated - you start flat with fresh cash.

FIX
  Apply the loaded state into the portfolio manager:

  def _load_previous_state(self):
      try:
          portfolio_state = self.state_store.load_portfolio_state()
          positions = self.state_store.load_positions()

          # Restore cash first (must exist before positions for weights)
          if portfolio_state:
              cash = float(portfolio_state.get("current_cash", 0.0))
              self.portfolio_manager.update_cash(cash)
              self.initial_cash = float(portfolio_state.get("initial_cash", cash))

[H-1] Sortino / downside deviation is wrong (3 copies)
Files: monitoring/metrics.py::calculate_sortino_ratio
       backtest/enhanced_engine.py::_calculate_metrics
       risk/metrics.py::calculate_sortino_ratio
---------------------------------------------------------------------
PROBLEM
  All three compute downside risk as std(returns[returns < 0]). Correct
  downside deviation is sqrt(mean(min(r - target, 0)^2)) over ALL observations
  (positive returns contribute 0, they are not dropped). Using std of only the
  negatives re-centers around the subset mean and discards the zeros, biasing
  the risk estimate. The three modules agree with each other but are all wrong.

FIX (canonical implementation):
  def calculate_sortino_ratio(returns, risk_free_rate=0.0,
                              periods_per_year=252, target_return=0.0):
      returns = pd.Series(returns).dropna()
      if len(returns) < 2:
          return 0.0
      rf_per = risk_free_rate / periods_per_year
      excess = returns - rf_per
      downside = np.minimum(excess - target_return, 0.0)      # all obs
      downside_dev = np.sqrt(np.mean(downside ** 2)) * np.sqrt(periods_per_year)
      if downside_dev == 0:
          return 0.0 if excess.mean() <= 0 else float("inf")
      return (excess.mean() * periods_per_year) / downside_dev
  Apply the same downside_dev in enhanced_engine._calculate_metrics and
  risk/metrics.py so all three match.

[H-2] Alpha can become NaN/complex for negative cumulative returns
File: monitoring/metrics.py::calculate_alpha_beta
---------------------------------------------------------------------
PROBLEM
  alpha = annualized_return(excess_strat) - beta*annualized_return(excess_bench)
  where calculate_annualized_return does (1+r).prod() ** (1/years) - 1. If the
  cumulative excess return is negative, raising a negative number to a
  fractional power yields NaN (or complex). Alpha silently becomes NaN.

FIX (use arithmetic annualization, matching enhanced_engine.Benchmark):

  rf_daily = risk_free_rate / periods_per_year

        - beta * ((r_bench.mean() - rf_daily) * periods_per_year)
  return alpha, beta

[H-6] Kelly criterion uses the wrong variance
File: decision/sizing.py::kelly_criterion_position
---------------------------------------------------------------------
PROBLEM
  kelly_f = predictions / np.var(predictions)
  Kelly is mu / sigma^2 where sigma^2 is the ASSET'S return variance, not the
  cross-sectional variance of the prediction vector. Dividing by var(predictions)
  couples every position size to the whole batch - adding an unrelated asset
  changes all sizes. It also ignores the win_rate/avg_win/avg_loss params.

FIX
  Pass per-asset volatility in and use it:
  def kelly_criterion_position(predictions, volatility, fraction=0.25,
                               max_position=1.0, **kwargs):
      vol_safe = np.maximum(np.asarray(volatility), 1e-6)
      # approximate Kelly for Gaussian returns: f* = mu / sigma^2
      kelly_f = np.asarray(predictions) / (vol_safe ** 2)
      positions = np.clip(fraction * kelly_f, -max_position, max_position)
      return positions
  Update create_positions to route volatility into the kelly branch.

  on_prediction append to self._market_events / self._signal_events from the
  caller thread. Plain list append/pop(0) without a lock is a race (lost
  events, IndexError). OrderManager sets self._lock = None and never locks,
  but broker callbacks can update orders concurrently.

FIX
  Use thread-safe queues:

      self._market_events = queue.Queue()
      self._signal_events = queue.Queue()

      self._market_events.put(event)
      # consumer loop:
      try:
          event = self._market_events.get(timeout=0.1)
      except queue.Empty:
          event = None
  In OrderManager:
      import threading
      self._lock = threading.Lock()
      with self._lock:
          ... mutate self._orders / self._positions ...
